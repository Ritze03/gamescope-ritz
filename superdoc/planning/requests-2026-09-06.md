## For the user to test (cannot be verified here)

Everything below needs a real game, a real desktop session, or both — none of it can
be driven from a headless instance with a synthetic client.

1. **CS2 mouse-drift check** (carried over from `requests-2026-09-05-round2.md`
   item 8 — still open, not re-touched this pass):
   1. Launch CS2 through the new build, with force grab cursor **off** (the report's
      setup).
   2. In the menus, move the mouse: the pointer should track normally.
   3. Enter a match (or a practice map) and move the mouse: the view must follow the
      mouse only — no drifting or snapping back towards the centre, no "joystick"
      motion when the mouse is still.
   4. While in the match, open the overlay and change the resolution
      (Display > Resolution), and also switch the scaler to Stretch and back
      (Display > Upscaling > Scaler): the view must not jump when the change applies.
   5. Repeat step 3 with the stretched resolution **on** and **off**.
   6. Repeat step 3 with Cursor > Override game cursor **off** and **on**.
   7. Back in the menus after the match: the pointer must track normally again.
   If anything still drifts: `gamescopectl wlserver_pointer_stats` while it happens —
   `constraint=locked` with `warps_suppressed_locked` climbing as you move means the
   host is still delivering absolute samples to a locked game.

2. **Profiles scenario, a real game.** Create two general profiles (e.g. `Comp` and
   `Casual`) with a visibly different setting each (crosshair colour is easiest to
   see). Create a game profile for CS2 (or whatever you have) inheriting one of them.
   Launch the game, edit something in its profile, alt-tab out and switch to the
   other general profile in the overlay, edit something there, switch back into the
   game's profile: your edit should be intact and the other profile's edit should not
   have leaked in. This repeats the headless scenario in `profiles/results.txt`
   above end-to-end, with a real game actually running.

3. **Item 16, Dynamic on a dark CS2 workshop map.** Shaders → Adaptive Brightness →
   `Dynamic`, defaults. Expect the map to become readable without the lights or the
   sky blowing out; if it looks too flat, raise Max gain or lower Target.

4. **Item 16, Dynamic on a bright CS2 workshop map.** Same setting. Expect it a step
   darker and calmer, shadows still there (Min gain sets how far they may drop).

5. **Item 16, Rust at night.** `Dynamic` with the default 1 s speeds. Watch a torch
   or a campfire coming into view — the picture should dim smoothly and never pump;
   if it reacts too slowly, shorten "Adapt to brighter".
