## [~] 1. CS2 in-game mouse STILL drifts back to centre

> Still broken. Same behavior.

The 2026-09-06 fix (`c81391e`, gating warps while a pointer lock is active) was
verified against a Wayland client holding `zwp_locked_pointer`; CS2 runs under
Xwayland, so the emitter or the lock detection differs there. Re-root-cause on the
Xwayland path.

**Reproduced headless, with the binary the user tested** (`tests/pointer_grab_client_x11.c`,
native SDL3 in relative mode under gamescope's Xwayland -- CS2's stack -- with an XI2 tap):
the `c81391e` client locked *before* it ever saw a pointer event; CS2 is a **menu first**.
Xwayland feeds absolute motion through one X slave device and relative motion through
another, and the master pointer copies the classes of whichever posted last; SDL3 caches
the master's axis mode at the first raw event it sees (in the menu) and never refreshes
it. This fork's `32b98bb` (2026-08-28, "relative only while locked") made the menu
absolute-only -- and with force-grab off the host-sample warp path always was -- so SDL3
cached the master as *absolute* and **differenced** the match's relative deltas: 10
injections of `dx=5` after 4 menu samples reached SDL as one `xrel=-592` (5 minus the last
menu position), then nothing, then a backwards kick on each change of direction. Not an
absolute event at all, which is why the warp gate could not touch it.

**Fix.** Relative motion accompanies every movement again -- `wlserver_mousemotion()`
unconditional (upstream verbatim), and `wlserver_mousewarp()` sends the clamped travel as a
relative event before its absolute notify (covers force-grab off, which upstream never did).
Xwayland then routes both halves through the relative slave, posts no second raw event, and
the master never changes device. `wlserver_pointer_stats` gains `relatives=`
(`relatives >= motions` always). The `c81391e` gate is kept.

**Desktop-verified** (headless, private sway): pre-fix `axis0=abs`, 10 x `dx=5` -> one
`xrel=-592`; fixed `axis0=rel`, 10 x `xrel=5.0`, 5 x `yrel=7.0`, by ConCommand and through a
real virtual host mouse (`tests/virtual_pointer_tool.c`, `zwlr_virtual_pointer_v1` into the
private sway) with force-grab off and on. `scripts/pointer-regression.sh` grew `x11-menu-lock`,
`x11-locked-abs`, `x11-host`; all checks pass. Evidence:
`build-release/verify-shots/pointer-regression/x11-explore-20260906-*`. Docs:
`cursor-pipeline.md` "The device SDL3 remembers". CS2 itself cannot run here -- laptop
check below.
