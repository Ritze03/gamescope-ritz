## [x] 1. Clipboard sync, Wayland and X11

Sync the clipboard between gamescope-ritz and the host system, working for both
Wayland and X11 clients.

Preferred: **hook the clipboard** so we are called when it changes, and sync on
that event. If no such hook exists, fall back to syncing on focus transitions —
gamescope → system on focus loss, system → gamescope on focus gain (focus meaning
focus to gamescope-ritz itself).

**Decided 2026-09-04:** `CLIPBOARD` only — the normal Ctrl+C/Ctrl+V buffer. Not
the X11/Wayland `PRIMARY` (select-to-copy / middle-click) selection.
`Why:` primary updates continuously while drag-selecting, which is a lot of
surface area for a buffer most users never think about.

## [x] 2. Shader: vibrancy range

Limit vibrancy to a maximum boost of **3.0**, and make the baseline **1.0**
instead of 0.0.

**Decided 2026-09-04:** range **0.0–3.0, neutral at 1.0** — a true saturation
multiplier, so 0.0 is greyscale, 1.0 leaves the image untouched, 3.0 is maximum
boost. `Why:` the user chose to keep desaturation reachable rather than clamp the
slider to boost-only.

## [x] 3. Shader: brightness / shadow control

A darkness booster for dark games.

**Decided 2026-09-04:** it **lifts shadows** — brightens dark areas so detail in
dark games becomes visible, leaving highlights alone. `Why:` "for dark games"
means seeing *into* the dark, not crushing it further.

## [x] 4. Bug: HUD outline is offset

The FPS display's outline is offset — currently too far toward the top-left.
Clearly visible at a large font size with a large outline.

**Measured 2026-09-04 on the test laptop** (binary `d0a86a4+`, includes
`4c51df4` "align the FPS outline stamps to whole pixels"). Method: `hud.font_size`
48 and 10, `hud.outline_strength` 4, 1 and 0.25, a 2-digit (60) and 3-digit (999)
reading, backdrop on so the outline (opaque black) reads against the backdrop's
near-black fill instead of true black; ink bounding boxes measured with PIL, not
eyeballed.

- **Concentric — the top-left lean is gone.** At outline 4 (font 48) and outline
  1 (font 10), the outline extends **exactly the configured radius, in whole
  pixels, on all four sides**, at both digit counts. No residual left/top bias
  at any setting tested.
- **New, smaller issue found by this measurement: outline 0.25 draws no
  outline at all.** `std::round()` on a per-stamp offset whose magnitude never
  exceeds 0.25px rounds every one of the 8 ring stamps to `(0, 0)` — they land
  exactly on the fill's own position and are fully painted over by it. This is
  a rounding-fix side effect, not the original top-left-lean bug: anything
  below `outline_strength` 0.5 now renders **zero** outline instead of a faint
  one. Not fixed here — measurement only, per the task.

Captures + the measuring script are in this session's scratchpad
(`/tmp/.../scratchpad/hud/`, `v3_*.png` + `measure.py`); not copied into the
repo since they're throwaway verification artifacts, not project assets.

## [x] 5. QoL: RGB sliders instead of HSV

Change the current HSV colour-selection sliders to RGB ones, keeping the same
preview style. RGB is easier for new users.

**Decided 2026-09-04:** the **accent colour stays a hue slider**. `Why:` accent is
stored as a single hue driving the whole OKLCH palette, with saturation and
lightness derived to keep the UI coherent; RGB there would mean rebuilding that
model. This change covers the full-colour HSV pickers only.

## [x] 6. Bug: the custom cursor is overridden in Rust

The custom cursor does not work in Rust (the game) — the game still somehow
overrides it. Reported 2026-09-04, after the original five.

**Testing note:** Rust cannot be run on the test laptop (anti-cheat, and the
laptop's CPU is too weak), so this one needs either a reproduction with a client
that sets its own cursor the same way, or verification by the user on the desktop.
Do not claim it fixed on the strength of a synthetic repro alone — say which was
used.

**Scouted 2026-09-04.** `cursor_everywhere` only rewrites the **root window**
fallback (`XDefineCursor` on the root, `steamcompmgr.cpp:1799`). Any window that
sets its own cursor beats the root, and Wine's winex11 driver always does. The
live compositing path still reads `XFixesGetCursorImage()` every frame and paints
whatever the current cursor is. So the reported behaviour is the documented,
intended scope — see `superdoc/features/cursor-pipeline.md`.

Rust splits into two cases:
- **Pointer locked (gameplay)** — there is no cursor layer at all. The absolute
  pointer is frozen, every cursor source stands down, and the crosshair is drawn
  into the game's own frame. **Not fixable by any compositor.**
- **Pointer free (menus)** — Unity under Proton sets a real X11 cursor on its own
  window, which we then composite instead of ours. Fixable.

**Decided 2026-09-04: add an opt-in override.** A setting separate from
`cursor_everywhere` that substitutes our cursor on the live compositing path
rather than the root fallback. `Why:` the user accepted the trade — it also hides
games' own meaningful cursors (RTS unit cursors), which is why it must be its own
opt-in and not a silent widening of `cursor_everywhere`. It fixes menus only and
does nothing during locked-pointer gameplay; that limit must be stated in the
setting's own help text, not just here.

Discriminator if ever needed: `gamescopectl paint_cursor_plane 0` — cursor
disappears means the cursor plane owns it (fixable), cursor stays means the game
painted it into its frame (not fixable).

**Deferred, and genuinely not testable here:**

- **Rust itself** (item 6's original report). Anti-cheat and CPU rule out the
  laptop. The mechanism it exercises — a client setting its own cursor through
  `XDefineCursor`, which is what Wine's winex11 driver always does — was
  reproduced with `xterm -xrm '*pointerShape: gumby'` and the override replaced
  it correctly. **Needs the user's own confirmation in Rust's menus.** It will
  not help during locked-pointer gameplay, and cannot: there is no cursor layer
  then, for any compositor.
- **The DRM/embedded path** for the invert blend and the cursor override. Every
  test so far is nested. DRM's partial-composition guard is reasoned, not
  observed.
- **A GNOME/Mutter host** for clipboard sync, where the `wl_data_device`
  fallback rather than data-control would be exercised.
- **`cursor_everywhere`'s pure root-window case** — a spawned client always
  filled the nested surface, so "hover true root background" was unreachable.
  That path is untouched by this batch's diff.
