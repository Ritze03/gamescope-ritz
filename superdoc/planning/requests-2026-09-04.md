## [ ] 1. Clipboard sync, Wayland and X11

Sync the clipboard between gamescope-ritz and the host system, working for both
Wayland and X11 clients.

Preferred: **hook the clipboard** so we are called when it changes, and sync on
that event. If no such hook exists, fall back to syncing on focus transitions —
gamescope → system on focus loss, system → gamescope on focus gain (focus meaning
focus to gamescope-ritz itself).

**Decided 2026-09-04:** `CLIPBOARD` only — the normal Ctrl+C/Ctrl+V buffer. Not
the X11/Wayland `PRIMARY` (select-to-copy / middle-click) selection.
`Why:` primary updates continuously while drag-selecting, which is a lot of
surface area for a buffer most users never think about.

## [ ] 2. Shader: vibrancy range

Limit vibrancy to a maximum boost of **3.0**, and make the baseline **1.0**
instead of 0.0.

**Decided 2026-09-04:** range **0.0–3.0, neutral at 1.0** — a true saturation
multiplier, so 0.0 is greyscale, 1.0 leaves the image untouched, 3.0 is maximum
boost. `Why:` the user chose to keep desaturation reachable rather than clamp the
slider to boost-only.

## [ ] 3. Shader: brightness / shadow control

A darkness booster for dark games.

**Decided 2026-09-04:** it **lifts shadows** — brightens dark areas so detail in
dark games becomes visible, leaving highlights alone. `Why:` "for dark games"
means seeing *into* the dark, not crushing it further.

## [ ] 4. Bug: HUD outline is offset

The FPS display's outline is offset — currently too far toward the top-left.
Clearly visible at a large font size with a large outline.

## [ ] 5. QoL: RGB sliders instead of HSV

Change the current HSV colour-selection sliders to RGB ones, keeping the same
preview style. RGB is easier for new users.

**Decided 2026-09-04:** the **accent colour stays a hue slider**. `Why:` accent is
stored as a single hue driving the whole OKLCH palette, with saturation and
lightness derived to keep the UI coherent; RGB there would mean rebuilding that
model. This change covers the full-colour HSV pickers only.
