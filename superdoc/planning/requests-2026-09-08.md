## [x] 8. HUD margin measures past the readout, not to it

Not a user request in this file's own numbered list -- a bug report handed down from the
orchestrator: *"the FPS HUD draws 2 pixels too far away from the vertical edge and one
pixel too 'less' from the horizontal edge."* Measured first rather than trusting that
framing, per the task brief, and the true shape turned out bigger and asymmetric between
axes rather than matching those exact counts.

**Definition nailed down:** the margin is the distance from the screen edge to the
*outermost drawn pixel* -- the backdrop rect if one is drawn, else the outline's outer
ring if one is drawn, else the glyph ink. See `superdoc/features/fps-display.md`'s new
"Margin" section for the full table of which element that is per configuration.

**Before** (font size 36, top-left anchor, backdrop off, outline off -- the case with no
crisp edge of its own to pin the margin to):

| margin | measured left | measured top |
|---|---|---|
| 0 | 7 | 14 |
| 5 | 12 | 19 |

Root cause: `backdrop_padding` (6px) was always added whether or not a backdrop was
actually drawn, plus the glyph's own side bearing/cap-height gap that
`ImFont::CalcTextSizeA()` cannot see (it measures the advance box, not the ink box). The
backdrop-ON case was already exact -- `AddRectFilled` with no rounding takes ImGui's
`PrimRect` fast path (no antialiasing), and the box's own placement math puts that rect's
edge at the configured margin regardless of anything else.

**After** (same configuration):

| margin | measured left | measured top |
|---|---|---|
