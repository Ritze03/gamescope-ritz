One surface. You type, it appears.

Direction B replaces the dock and its six floating windows with a single centred Console. Ctrl+Shift+O opens it with the query line already focused; type sharp and the Sharpness slider is under your cursor two keystrokes later — adjustable in place, without opening anything.

↓ The first screen below is a working console. Click it and type — everything else on this page is a still.

Browsing did not go away: it is the same list with an empty query and an area chip. Because there is exactly one surface, and exactly one row grammar inside it, an inconsistent screen is not something you can accidentally build — the drawing API is not reachable from a call site.

06 — The gamepad answer

Typing is an accelerator, not the contract. The registry is the contract. Three distinct gamepad paths fall out of it, in the order you would actually reach for them mid-game.

Path 1 — the Quick Wheel: eight pins, no typing, sub-second

Hold L2 and the console does not open at all. Up to eight pinned entries appear as a radial at screen centre; the right stick selects, and the same ←→ semantics (now stick-X) change the value live while the game keeps running. Release to commit. These are exactly the pins Home lists — same registry, same rows, same value writer. This, not search, is the mid-game gamepad path.

Opening with the pad (Select+Start, or the Steam Deck’s … button) opens the same console in browse posture: the query line collapses into a breadcrumb bar and the body starts on the area grid. Path 3 — when you do want to search with a pad: the letter wheel

The last row of every area is Search within…. It opens a three-ring letter wheel: right stick picks a ring, face buttons or a second flick picks the letter — roughly 0.6 s per character. That is only usable because search narrows fast, and the registry lets us prove how fast: over the 147 entries in the shipping registry, 2 characters median / 3 characters at the 90th percentile is enough to put the target in the top three results. The console prints the live match count next to the wheel so you can stop as soon as you see “1 match”. A build-time assertion keeps this true: adding an entry whose 3-character prefix collides with more than 3 others fails the registry self-test until you give it a distinguishing keyword.

  • Every text field declares a non-typing fallback, or it does not compile into browse. area.Text() requires either .Suggestions(fn) (profile names offer Cyberpunk – Quality, Cyberpunk – 60 fps, generated from the app id and current settings) or .KeyboardOnly(), which hides it from gamepad browse and shows an inspector line saying so.   • Every numeric entry is a slider or a stepper first, a text field never. The taxonomy has no “type a number here” control — area.Number() renders a stepper and only offers raw entry on Enter from a keyboard.
  • Gamepad nav does not exist in the codebase today (ImGuiConfigFlags_NavEnableGamepad is never set, and no evdev pad reader is wired to the overlay). This is net-new work under any direction; this direction at least specifies it exactly once, for one row grammar, instead of six times for six panel layouts.

07 — The row taxonomy, on one sheet

The rule that makes an inconsistent screen hard to build: every option is one Row, and every Row is the same three-column grid — [gutter 6u | label, flex | control, 50u] — at one of exactly three heights: 10u compact, 14u expanded (only when selected, only if the type asks), 0 hidden. A control type may only change what is painted in the control column. It may never change the row height, the label position, the padding, or where help text goes. Help never appears in a row; it appears in the Inspector for whatever is selected. There are no tooltips.

Spacing rhythm

One unit: u = 4px × display_scale. Everything is an integer multiple, and no call site ever names a pixel. Row 10u · row v-padding 1u · gutter 6u · control column 50u · console padding 3.5u · query line 14u · group header 8u + 1.5u gap · inspector 16u · stream line 5u · gauge card gap 0.75u.

Elevation: exactly two levels

  • Level 0 — the game, blurred and veiled by gamescope’s own compositor pass (FrameInfo_t::blurRadius + the darkening multiply that PanelConfig.cpp already drives). This is the signature and it costs the overlay nothing: the blur is not per-window backdrop-filter, it is a full-screen pass on the game layer, which is precisely why a single centred surface reads better than six floating windows over it.
  • Level 1 — the Console. That is the whole list. Panes live inside the console body; they do not float. There is no z-order, no focused-vs-unfocused window opacity pair, no “which window has focus” question, and therefore no way for two screens to look different from each other.
  • The two opacity settings the user already has (focused 1.00, unfocused 0.90) collapse to one: overlay.opacity_console. opacity_dock (0.70) is retired with the dock; blur (1.0) and darkening (0.8) keep their exact meaning.

Nine roles, two families, three weights. That is two fewer than Fonts.h’s current ten, and it drops the 8px DockHotkey face entirely with the dock — a real atlas saving that pays for the two new roles. Hard rule kept from the spec: Mono carries every number, unit, state word, path and id; Sans carries prose only. Because Mono is genuinely monospaced, every value column is tabular for free — which is why a list of 147 rows does not shimmer while a slider is being dragged.

State treatment — selection is focus

StateTreatment
idlerow transparent, label text/label, control at its own resting colours

selectedrow fill accent 10%, 2u accent/base left edge, label to text/primary, gutter dot lit. Keyboard, gamepad and pointer share one cursor — so there is no separate focus ring to design, and no “focus vs. selection” disagreement to debug.

disabledwhole row × 0.34 alpha, control fills go neutral white (existing rule, §12). Never hidden. Inspector states the predicate that is false.
changed-this-sessiongutter shows a 6×6 accent/base dot instead of nothing — the only per-row decoration in the whole design, and it answers “what did I already touch?” without a second colour

Motion — three durations, one curve, a closed whitelist

  • quick 90 ms · settle 160 ms · instant 0. One easing, applied frame-rate-independently as 1 − exp(−dt · rate), not a naive lerp against io.DeltaTime (which changes speed with frame rate — a real hazard at 30 vs. 240 fps).
  • Exactly four animations exist, and the helper owns all four: the selection cursor sliding between rows (settle), a row expanding 10u→14u on selection (settle), a value bar filling to a new value (quick), and the console fading in on open (quick). An animation that is not on this list cannot be written, because PaneCtx exposes no timing primitive.
  • Query→results is deliberately not animated. Text you are reading must not move.

Two documented departures at the extremes, both decided by the helper, not the caller: at display_scale ≤ 0.7 the Inspector drops from 3 lines to 2 and the group-header count is suppressed; at ≥ 1.6 the control column widens from 50u to 58u so the expanded slider’s min/max marks still fit without ellipsis. Console width is min(900 px × display_scale, 0.62 × output width), height min(auto, 0.82 × output height), so it never crowds the HUD at 2.0× on a 1080p panel.
